Press Run and the program is compiled twice, entirely in this tab. On the left it becomes JMVM bytecode for the interpreter. On the right the same Stage-4 Retag goes through retag2wasm, a code generator written in Sapl that emits a WebAssembly module directly: no C compiler, no Binaryen, no server. The browser then compiles that module to machine code.

Good to know

      
    
        
  • Run times are the best of three runs on each side (the first run of fresh code is slower); compile times
          are listed separately. The JMVM time is the VM's own measurement of the program, without loading.
    • 
        
  • The JMVM keeps its own stack in memory. The generated WebAssembly uses the browser's call stack, which is
          small (about 1 MB; the module therefore runs in the page, not in a worker); very deep programs such as
          sort and twice stop there with a message. While it runs, the page does not respond. A version that keeps its own stack is a next step.
    • 
        
  • Not yet supported by retag2wasm: try/catch and floating-point
          literals. The JMVM column runs them as usual.
    • 
        
  • More background: the WebAssembly backends factsheet.
