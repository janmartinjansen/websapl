1. Pipeline Architecture

The compilation chain bridges Clean's graph-rewriting abstract machine (Clean ABC) to the register/slot-based execution model of the JMVM:

Clean Source (.icl)
→
Clean Frontend (clm / abcopt)
→
Clean Bytecode (.opt.abc)
→
abc2retag.py
→
Stage-4 Retag AST (.cfp_retag)
→
Stage 5 Codegen (compile-retag)
→
JMVM Bytecode (.jmvm)

2. Why Retag? (The Architectural Rationale)

The Impedance Mismatch Between ABC and JMVM

Clean ABC is an abstract machine designed specifically for graph reduction. It employs a dual stack architecture:

  • A-Stack: contains pointers to heap graph nodes, closures, and evaluation thunks.
  • B-Stack: contains unboxed primitive values (integers, booleans, characters).

Because Clean functions receive arguments across both stacks without named local variable slots, Clean ABC code is heavily saturated with stack-shuffling opcodes: swap_a, exchange_a, dup_a, updatepop_a, updates2_a, updates3pop_a, push_update_a, and push_b2.

JMVM, on the other hand, is an expression-oriented virtual machine with indexed local variable slots inside structured activation frames (load <idx>, store <idx>). Pattern matching is dispatched directly via constructor tags (case, jmpt).

Why Direct Stack Emulation (abc2jmvm.py) Failed to Scale

The initial prototype (abc2jmvm.py) attempted to emit JMVM bytecode instructions directly opcode-by-opcode, emulating the A- and B-stacks at runtime in memory slots. This caused three critical bottlenecks:

  1. Excessive Memory Loads & Stores: Every Clean stack manipulation (e.g. push_a, update_a, swap_a) turned into active memory accesses within activation frames.
  2. Instruction Explosion: On algorithmic benchmarks like sort, stack-shuffling resulted in an astonishing 9,670,000,000 instructions executed, taking 6.5–7.3 seconds.
  3. Fragile Calling Conventions: Complex control flow with multi-entry loops and tail calls required intricate ad-hoc patching, leading to premature termination bugs on benchmarks like knights.

The Breakthrough: Symbolic Decompilation to Stage-4 Retag

By shifting the target to Stage-4 Retag Core AST (.cfp_retag), abc2retag.py solves these challenges fundamentally:

  • Total Stack Evaporation: The decompiler tracks the A- and B-stacks symbolically at compile time. All intermediate stack shuffling operations evaporate completely, leaving clean, functional let-variable bindings and expression trees.
  • Leveraging Battle-Tested Codegen: The existing Stage-5 compiler (stage5_codegen.cfp) already contains sophisticated algorithms for local frame slot allocation, tail-call optimization (jmpt), and closure/thunk construction.
  • Interprocedural Strictness Preservation: Clean's front-end strictness analyzer annotations (!x) are preserved and fed directly into Stage 5, generating unboxed evaluation paths natively.

4. Advanced Functional Patterns Handled

Cyclic Graph Knot-Tying (hamming & eval2)

In Clean, infinite streams and cyclic environments are created by allocating an uninitialized graph root (create), passing it as an argument to downstream thunks (e.g. c21 root), and filling it afterwards (fillh / fill). abc2retag.py detects unfilled cyclic slots and binds them to direct let variables. Stage 5 Phase B (genLet) emits JMVM's native cycle knotting (push 666 followed by an in-place update).

Tail Recursion Modulo Cons (TRMC, sprimes)

Clean optimizes list generation loops by lazily instantiating constructor cells with a destination hole and jumping into the next iteration with the hole passed as an argument. The decompiler tracks destination slots across tail calls (jmp) and final returns (rtn), generating clean recursive functional expressions.

Lazy Higher-Order Combinators (parsetest & prolog)

Recursive parser combinators construct lazy function applications via e_system_nAP. The decompiler translates these into lazy thunks (__ap2 f x = eval(f x)), preventing premature eager evaluation during grammar construction.

Polymorphic Strings & Character Arrays

Clean's ARRAY CHAR operations are lowered to JMVM's native heap-allocated string primitives: strlen, strat, update, strappend, strcreate, along with recursive content equality __eqAC (since JMVM pointer equality == compares references rather than string characters).

5. How to Use It

What you need

  • Clean 5.1 to turn .icl into ABC. The Clean compiler only exists for Linux x86-64 (and Windows). On a Mac it runs in a small Lima VM with qemu-user; the full recipe is in experiments/clean_vergelijking/README.md (section “Getypeerde gen1”), and experiments/clean_vergelijking/setup_clean.sh installs Clean from TOP's package registry.
  • A built JMVM in the repository root (make: run, runfast, runfast-big, jmvm2jvb) and Python 3. Run everything from the repository root.

The four steps

# 1. Clean -> optimised ABC (on Linux / in the VM); writes "Clean System Files/prog.opt.abc"
clm -nt -optabc -bytecode prog -o prog

# 2. ABC -> Stage-4 retag
python3 experiments/abc2jmvm/abc2retag.py "Clean System Files/prog.opt.abc" -o prog.cfp_retag

# 3. retag -> JMVM bytecode (.jmvm and .jvb)
./compile-retag prog.cfp_retag prog.jmvm

# 4. run (or ./run for instruction counts)
./runfast prog.jmvm

Step 1 also produces prog.bc for Clean's own ABC interpreter, which is handy as a reference: abci-interpret prog.bc must print the same value. clm prints “Can't execute the linker” in the VM; that only concerns the native executable and can be ignored.

Large programs: ./compile-retag runs the retag compiler on the standard VM. For a program the size of gen1, call it with the large-heap VM instead: printf 'prog.cfp_retag\nprog.jvb\n' | ./runfast-big sapl_compiler/retagcomp.jmvm, and run the result with ./runfast-big prog.jvb.

A program that works

module squares2
import StdOverloaded, StdClass, StdInt, StdBool

:: L a = Nil | Cons !a (L a)

upto :: Int Int -> L Int
upto a b = if (a > b) Nil (Cons a (upto (a + 1) b))

sumSq :: (L Int) -> Int
sumSq Nil = 0
sumSq (Cons x xs) = if (x rem 2 == 1) (x * x + sumSq xs) (sumSq xs)

Start :: Int
Start = sumSq (upto 1 1000) rem 1000007

Through the four steps this prints res: 665338, the same as abci-interpret. Start may be an Int, a list (printed element by element), or *World -> *World with file I/O through StdFile (as in the gen1 port).

Current limitations

  • One module. Only the main module's .opt.abc is translated. Functions from StdEnv modules (sum, map, ++, list comprehensions over [1..n], …) live in other modules and are not linked in yet; the working programs define such helpers themselves, as above. Integer arithmetic, comparisons, strings ({#Char}), records, ADTs, higher-order functions and laziness work.
  • A subset of ABC. The decompiler handles the instructions that the 13 benchmarks and gen1 use. Anything else stops with onbekende ABC-instructie: … (for example andIio, which Clean generates for isOdd). Floating point (Real) is not supported yet.
  • Errors. A Clean abort becomes a JMVM nomatch: the program still stops, but without Clean's message.

Measuring and switching optimisations off

# all 13 benchmarks plus both gen1 ports (output check, fixed point, counts)
python3 experiments/abc2jmvm/meet.py --gen1 --vergelijk experiments/abc2jmvm/basislijn.tsv

# one optimisation off, for an A/B comparison
python3 experiments/abc2jmvm/abc2retag.py prog.opt.abc -o prog.cfp_retag --uit=wrappers

# a small Sapl program through Clean, abci and abc2retag side by side
bash experiments/clean_vergelijking/typed_toets/route.sh prog.cfp

The optimisation steps are fold (constant folding), wrappers (collapsing nX → eaX → sX chains), evals/params/velden (dropping eval where a value is certainly evaluated) and eager (computing x + 1 directly instead of via a thunk), inline (inlining small functions, in particular closure entries), thunkdoor (pointing a thunk straight at the real function) and bshare (sharing copied calls on the B-stack). Details: docs/2026-11-08_abc_naar_retag_perf_plan.md.
