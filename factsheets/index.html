Sapl to native code via C: one C function per Sapl function

gen1’s retag form translated to C on the JMVM’s own memory model and GC (optionally the VM’s own runtime code). All 13 core benchmarks run in 0.34× the interpreter’s time, faster than Clean’s native code generator and on par with GHC, and the Sapl compiler compiles itself natively in 248 ms (12 November 2026).

How can a simple, small compiler compete with Haskell and Clean?

Why sapl2c (~2,000 LOC) matches GHC -O2 (1.02×) and beats Clean native (0.87×): whole-function C for clang -O2, MUSTTAIL + 2-register ABI, non-pointer spill elimination, cache-hot 8 MB Cheney nursery, and where GHC/Clean still lead.

What is the secret behind sapl2c’s performance?

Not one secret but three multiplying factors: the Retag format unlocks clang -O2 (same clang from bytecode: 442 vs. 248 ms), a cache-hot Cheney nursery makes memory fast, and Sapl leaves little abstraction to compile away. Plus where static types still win.
