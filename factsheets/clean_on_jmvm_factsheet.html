1. Architecture: Dual-Engine Clean Pipeline

Both execution paths share the exact same Clean frontend and ABC optimizer, enabling apples-to-apples performance and correctness comparisons in both the browser UI (server.py) and the Node.js CLI runner (cli/run_clean.js):

Clean source (.icl)
   │
   ▼  cocl.pbc (official Clean compiler + base-stdenv-2.2.1)
 .abc
   │
   ├──► [ABC Route]   abcopt ──► bcgen / bclink / bcprelink ──► abc-interpreter.wasm
   │
   └──► [JMVM Route]  abcopt ──► abc2retag ──► retagcomp.jvb ──► jmvm.wasm

In clean-sandbox’s original make.icl, abcopt was skipped before bcgen (causing fib to take ~2393 ms on ABC). Enabling abcopt_bestand.bc on both routes by default (toggleable via --no-abcopt in cli/run_clean.js) puts both interpreters on equal footing.

3. Ecosystem Potential & Remaining ABC Coverage

  • 2×2 Frontend/Backend Matrix: JMVM now serves Sapl, Haskell-lite, and full Clean, while Sapl/Haskell can also target ABC/native via sapl_naar_abc.py.
  • Generics Working: abc2retag.py now supports .desc0, exported module constructors (Con_ prefix), cross-module extern_con linking, and StdGeneric’s LEFT/RIGHT ADT grouping.
  • Remaining ABC Gaps (83 opcodes currently supported): abcopt stack/jump shorthands (updatepop_a/b, pop_a_rtn, etc.), floating-point (StdReal), Char comparisons, bitwise ops (and%, shiftr%, ...), array replace, and indirect calls (jsr_i, jmp_i).

4. Dynamics & graph-copy: Role Division for iTasks

Clean’s built-in Dynamics (_SystemDynamic) and graph-copy are tightly coupled to ABC descriptor tables, runtime type unification (eqD_b, jmpD, update_nc, select_nc), and Clean’s RTS memory layout. Emulating that binary machinery directly inside JMVM would be a substantial separate effort.

JMVM-Native Alternative: Functionally equivalent behaviour can be achieved cleanly using pack / unpack (serializing and deserializing JMVM’s uniform tagged heap graphs and closures directly) paired with a custom Dynamic whose TypeRep is derived via Clean Generics (StdGeneric) — which now runs natively on JMVM.
