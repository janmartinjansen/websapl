The JMVM Interpreter: Anatomy, Line Counts & Execution Model

The JMVM is the only C/C++ component in the entire Sapl ecosystem. While a raw directory count of vm/ reports 21,939 lines, over two-thirds of that is generated dispatch code, compiled bytecode and binaries. The actual browser VM runtime is 5,244 lines of handwritten C/C++ (6,620 lines including the legacy text loader).

4. Execution model and why it is fast

Memory layout & tagging (waarden.h, heap.h)

  • 2-bit LSB tags: 00 = 62-bit signed integer (direct arithmetic without shifting), 01 = heap pointer, 10 = 32-bit float (shifted by 2), 11 = character.
  • Two-space Cheney copying GC: linear bump-pointer allocation; overflow and stack guards sit in separate noinline, cold functions so the dispatch loop keeps its hot registers.
  • Catchable VM faults: try/catch around runLoop (never inside it; placing C++ try inside the loop cost 18% on queens due to register spills).

Laziness isolated in two instructions

  • eval (eval.c): the only place a thunk is reduced. It loops on the VM’s own control stack (csp), so arbitrary lazy chains never overflow the C stack.
  • jmpt (sprong_aanroep.c): constructor jump table updating hv = mark = sp; handles case in a single instruction.
  • Everything else is eager: arithmetic, jumps, calls and node construction know nothing about thunks or partial applications.

Single source of truth for three engines: All 45 active regular opcodes, 7 superinstructions, 1 deprecated ABI slot (FDIV) and 39 _AUX primitives live in vm/instructies.tab (142 lines). No single interpreter wins in every browser. The JMVM is fastest in Safari and depends least on the browser (Safari 0.98×, Firefox 1.45× its time in Chrome). In Chrome, Clean’s interpreter with locals is fastest (0.65× the shipped one); in Firefox the shipped abc-interpreter.wasm is fastest, and locals cost twice the time there (spilling). The Emscripten build behaves like the locals version, slightly worse. So the ABC interpreter build should be chosen per browser engine. On Sapl programs translated to ABC the picture is the same, with the ABC about 15% slower than Clean’s own. Safari does not release the memory of old wasm instances within one page.
