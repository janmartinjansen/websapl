How Can a Simple, Small Compiler Be Competitive with Haskell and Clean?

sapl2c is 1,146 lines of Python (or 1,809 lines of Sapl) plus an 818-line C runtime header — orders of magnitude smaller than GHC or Clean’s native code generator. Yet on Apple M4 it matches GHC -O2 (1.02×) and beats Clean native (0.87×). Here is why.

1. Six Reasons a Small Compiler Keeps Up with Giants

1. Piggybacking on clang -O2 at Function Level

GHC and Clean maintain huge, decades-old native backends for register allocation, instruction selection, and branch layout. sapl2c emits structured C one function per Sapl function from Stage-4 Retag, so clang sees whole functions, named locals, and case switches — doing the heavy silicon tuning for free.

2. Two-Register Return & Uniform MUSTTAIL ABI

Every function has the same signature: R f(hp, sp, a0..a5) where R = {v, hp} returns both value and heap pointer in hardware registers. Every tail call compiles to a direct jump (all 1,368 tail calls in gen1 verified as jumps), and self-recursion loops via goto top.

3. Tagged Primitives + Non-Pointer Proofs

2-bit tag bits keep integers, chars, and booleans unboxed without static type annotations. Crucially, sapl2c’s flow-sensitive non-pointer analysis (int, non-pointer, any) proves when locals cannot hold heap pointers, eliminating shadow-stack spills on hot numeric loops (zero spills in fib).

4. L1-Friendly Growing Cheney Nursery

Cheney copying allocation is just hp += N. Starting the heap at 8 MB (and growing 4× only when >10% survives GC) keeps the active nursery hot in CPU cache — unlike a 192 MB fixed arena. That change alone cut sprimes by 45%, match/prolog by 21%, and hamming by 18%.

5. Coalesced Heap Checks & Inline EVALK

Straight-line allocations are merged into a single HEAPFULL(N) check, and shadow-stack saves happen only on the slow GC path. Already-evaluated values pass EVALK with a single inline tag test, avoiding function-call overhead.

6. gen1 Already Did the Functional Heavy Lifting

sapl2c does not need its own strictness analyzer or lambda lifter: gen1’s Stage-4 Retag already encodes strictness (!), lifted helpers, CAFs (=:), and local cheap-thunk elimination (tagLazyMaybe, #157).

The Takeaway: You do not need a 100,000-line custom code generator to compete with GHC and Clean. A crisp, explicit Stage-4 Retag IR + a cache-friendly Cheney nursery + non-pointer spill elimination + a uniform MUSTTAIL ABI lets clang -O2 close the gap in under 2,000 lines of code.
