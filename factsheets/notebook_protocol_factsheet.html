The Notebook Wire Protocol

How the notebook page (JavaScript) talks to the Sapl interpreter: two kinds of request, one plain-text protocol of @@ lines, and a session that decides for itself which cells it must recompile and relink. Every example below is real traffic, captured from the production worker running the sieve of Eratosthenes.

1. Three hops, one interpreter

The page never compiles anything itself. It sends the whole notebook as text to a Web Worker. The worker owns a WebAssembly instance of the JMVM in which one Sapl program runs: the REPL in Sapl (repl_sapl/build/mini_repl), which contains the preprocessor, the compiler, the typechecker and the linker as modules. That program sits paused at readLine between requests, so its heap — the session, with all compiled cells and evaluated values — survives from one run to the next.

Hop 1 — page ↔ worker

Structured-clone messages with an id. Runs and events go through one queue (nbQueued), so an event never lands in the middle of a run.

Hop 2 — worker ↔ REPL

The worker writes the notebook to repl_sapl/gen/notebook_in.txt in the instance’s file system and feeds one line, :nb repl_sapl/gen/notebook_in.txt, with jmvm_rs_feed. An event is a single line :nbmsg <token> <event>.

3. The :nb text protocol

A notebook file is an ordinary Sapl+ file with //%% cell markers. notebook_core.js classifies each code cell as either definitions (a = at the top level, ::, import, …) or one expression, and writes a block per cell. Cell numbers are positions in the notebook, starting at 0. Markdown cells are never sent.

Input (page → REPL)

@@mode any|topOne letrec in any order, or top-to-bottom (a cell sees only earlier cells).
@@values <dir>Save evaluated =: values in this directory.
@@defsallReport the definitions panel for every cell, not just the recompiled ones.
@@def <cell>A definition cell; its text follows. Always sent, for every definition cell.
@@expr <cell> <n>An expression cell to evaluate as number n. Only the cells that must run.
@@type <cell>A type cell: one expression per line.
@@restore <name> <hash> <path>Appended by the worker: a saved value that may be put back.

Output (REPL → page)

@@begin n … @@end nThe result of expression n. No @@end means the cell failed, and the text in between is the message.
@@value, @@text, @@table, @@graphics, @@markdown, @@form, @@interactiveThe kind of the block that follows, inside a cell.
@@def <cell> <name> :: <type>A definition of a recompiled cell, with its inferred type.
@@defsame <cell>This cell was not recompiled; keep the panel it had.
@@deferror <cell> <msg>A definition cell that does not compile, or that uses one that does not.
@@typewarn, @@typeok, @@typeerrType warnings and the results of type cells.
@@saved, @@restored, @@stale, @@errorValue saving, a stale event token, an error outside the cells.
@@nbdoneThe run is complete.

Inside a cell, the output layer lib/notebook_glue.cfp prints the blocks. It shows a value by its type, which the typechecker supplies for each expression cell. Anything the cell prints itself becomes a plain-text block.

4. Walkthrough: the sieve, as it really goes over the wire

A seven-cell notebook based on the TOP presentation. Cells 0, 1, 2 and 5 are definition cells; cells 3, 4 and 6 are expressions.

//%%
import "lib/list.spp" as L
import "lib/text.spp" as T
//%%
sieve (p : rest) = p : sieve [ x | x <- rest, x % p != 0 ]

primes =: sieve (L.from 2)              // =: a CAF: computed once, shared
//%%
n = 12
//%%
L.take n primes
//%%
D.table ["k", "k-th prime"] [ [k + 1, p] | (k, p) <- L.take 4 (L.indexed primes) ]
//%%
crossOut k xs = if (k == 0) xs (case xs (Cons p rest -> Cons p (crossOut (k - 1) [ x | x <- rest, x % p != 0 ])) (Nil -> Nil))

tick ev k = case ev (D.Tick t -> k + 1) (_ -> k)
//%%
D.animated 500 0 tick (\k -> D.text (T.unwords (L.map T.showInt (crossOut k (L.range 2 30)))))

The model (here, the number of sieving steps) is never sent to the page. It lives in the session as a stepper: a function value that holds update, view and the current model. Each event applies it once, prints the new view and stores the next stepper under the token. Rerunning the cell dropped the stepper of its old token, so a late tick for 8_3 from run A is answered with @@stale 8_3 (captured), and the page stops that widget. Each run of a cell gives it a new token and starts again at model0.

5. How the session knows what to recompile and relink

Two separate decisions are made, in two places. The page decides which expressions to evaluate. The REPL decides which definition cells to recompile and link. Neither trusts the other, and both over-approximate: when in doubt, more is redone, never less.

Decision 1 — the page: which expressions run

dependents(cells, i) in notebook_core.js, a transitive closure by name:

  • a definition cell provides its top-level names, the constructors of its :: types, record getters and setters, and its import aliases (L, T);
  • a cell depends on it if any identifier in its text (strings and comments removed) is one of those names; L.take counts as using L;
  • a #import (textual, contents unknown) makes every cell depend on it;
  • “Run all” simply selects everything.

Expressions outside the set keep the output they showed. Every definition cell is always sent, because the REPL needs the whole notebook to know what changed.

Decision 2 — the REPL: what is recompiled and relinked

nbGo in repl_sapl/mini_repl.spp:

  1. Units. Definition cells that use each other form one unit (a strongly connected component, since “any order” is one letrec). The units are ordered so that every unit comes after the units it uses. In top-to-bottom mode, each cell is its own unit.
  2. Identity is the exact text. The session stores each unit as an entry whose identity is its source text. A unit whose text is found in the session is a candidate for reuse.
  3. Data files count. For each string literal that names an existing file (C.read "data/fruit.csv"), a line // data: <path> <length> <hash> is added to the cell’s text. If the file changes, the text changes.
  4. Changes propagate. A changed set collects the names of every unit that is recompiled (or that failed) in this run, plus the names of cells that disappeared. A unit is reused only if its text is known and none of its identifiers is in that set and it uses no import alias that was re-imported.
  5. Compile, then link immediately. A unit that is not reused is compiled to a chunk (.jvb bytes) and linked into the session image right away. A cell that the linker rejects is an error at that cell, and stays out of the session.
  6. Expressions are always new. All selected expressions are compiled together as one chunk per run, linked against the image and run, but never added to it.

Why changes must propagate: one consequence of linking names to addresses

The linker (laadformaat/link.cfp, written in Sapl) combines a chunk with the session image (Img, the table of names, addresses, CAF slots and types) in LK.lkLink. The result is code with absolute addresses and no open labels. The VM installs it with lookup "@install:…", appending it behind the existing code, and LK.lkSeal gives the new image. So a reused cell keeps pointing at the old code of everything it called. That is why a cell must be recompiled and relinked as soon as anything it uses was, even if its own text did not change. The ordering in step 1 guarantees that its dependencies are already in the new image when that happens.

The “recompiled” column is read straight from the output: @@def means recompiled, @@defsame means reused. Run A also starts the wasm engine, because the harness sent no NB_WARM beforehand (restarted = true). The output layer (lib/notebook_glue.cfp, cell −1) is an ordinary unit too. Consequences you can see in a notebook. Put an expensive =: value in a cell of its own, and editing a cell that it does not depend on will not recompute it. Changing a helper in the same cell (as in D), or a cell it depends on, starts it again from scratch. A CAF is a value, not a cached function call: after B, primes is the same lazily growing list.

6. Values across sessions (captured separately)

A fresh engine has an empty heap: after a page reload or a trap, every cell is compiled again. With @@values <dir>, the REPL writes each evaluated =: value with the pack primitive, and puts it back the next time if nothing it depends on changed. A one-cell variant with big =: L.nth 2000 primes:

Run 1 ← output (end)

@@saved big 1628192743-239 repl_sapl/gen/values/demo/big.1628192743-239.val

The worker keeps the bytes (NB_RESULT.saved: 129,302 bytes for the evaluated prefix of the infinite list primes, 37 for big). The page stores them in IndexedDB.

The hash (<hash>-<length>) covers the cell’s source, the hashes of the cells it depends on, and the libraries: the compiler and REPL code, the output layer and every imported module. The same “did anything I use change?” question from section 5 is thus asked across sessions. A value is put back only if its hash matches; otherwise the cell simply computes it again. The @@restore lines in run 2 are what the worker appends (nbWithRestores); the output is captured.

7. When things go wrong

Errors stay inside cells

  • Compile or link errors in a definition cell: @@deferror. Cells that use its names are not run either (F).
  • Run-time errors (error, and VM faults that can be caught): the cell’s try ends it without @@end (G).
  • An interactive step that fails: @@error, and the cell keeps its previous stepper.

A dying engine is replaced

  • A wasm trap (for example 1 / 0) kills the instance. The run returns the output so far with trapped = true, and the next run starts a fresh instance (restarted = true). The notebook itself is the log, so nothing needs to be replayed.
  • On restarted or trapped, the page stops all interactive widgets: their tokens belong to the old session.
  • A run that does not finish in time: the page keeps the cells that already reached @@end (from the progress stream) and marks the first unfinished cell.
