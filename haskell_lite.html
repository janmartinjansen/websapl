Haskell lite

Ordinary Haskell, type-checked and translated to Sapl+, running on the JMVM — natively, or in the browser without a server.

Haskell lite is a Haskell front-end for the JMVM, the stack-based virtual machine for lazy functional languages. It is meant for notebooks: small to medium programs, data exploration, teaching, trying out ideas. It is not a full GHC: the differences are listed at the end, and anything that is not supported gives a clear message rather than a wrong result.

A notebook cell

data Shape = Circle Double | Rect Double Double
  deriving Show

area :: Shape -> Double
area (Circle r) = pi * r * r
area (Rect w h) = w * h

main :: IO ()
main = print (map area [Circle 1, Rect 2 3])

Output

[3.1415927,6.0]

Trying it

In the browser. Open the example notebook in WebSapl and add a cell with + Haskell. A Haskell cell holds definitions or one expression. All Haskell cells of a notebook together form one module, so a cell may use definitions from any other Haskell cell. An expression cell shows its value; a cell that starts with do is run as an action (in IO) or shown (in Maybe, a list, Either).

In the Workbench (./start_workbench, the local IDE): the same notebook, with the translation on the server. If Haskell lite does not support something yet, the Workbench falls back to MicroHs; the status line says which route was used.

On the command line, from the repository root:

bash micro_haskell/hlite/hlite.sh Program.hs         # translate, compile, run
bash micro_haskell/hlite/hlite.sh --spp Program.hs   # only the Sapl+ translation

What it is

Haskell→ lexer→ layout→ parser→ fixity→ desugar→ type checker→ specialisation→ Sapl+→ gen1 compiler→ JMVM bytecode
  • Everything is written in Sapl+, the higher-level dialect of Sapl, and compiled to JMVM bytecode itself. In WebSapl the whole front-end runs inside the browser's WebAssembly JMVM.
  • Hindley–Milner type inference with type classes, following the Haskell 2010 report: let-polymorphism, the monomorphism restriction, defaulting (Num → Int, fractional classes → Double), superclasses, and higher kinds (Functor f, Monad m).
  • No dictionaries at run time. Overloaded functions are specialised per type for the whole program: == on an Int becomes a machine comparison, show on a Maybe [Int] a generated function for exactly that type. This is where the speed comes from.
  • Lazy evaluation, as in Haskell: infinite lists, where, sharing.
  • Translating and compiling a small program takes about 0.15 s natively; in the browser a notebook run is typically 0.3–1.5 s.

The language

What works, all checked against GHC:

  • Definitions: pattern matching (also nested, @-patterns, ~ and !), guards, where, let, case, if, lambdas, operator sections, local functions, mutual recursion, optional type signatures, type synonyms.
  • Lists: ranges ([1 ..], [0, 0.5 .. 2]), list comprehensions, strings as lists of characters.
  • Numbers: Int and Double; div, mod, fromIntegral, realToFrac, sqrt, sin, pi, round, truncate, ^, …
  • Data types: data with deriving (Eq, Ord, Show, Enum), records (create, update and match), type synonyms.
  • Type classes: the standard classes (Eq, Ord, Show, Num, Integral, Fractional, Floating, RealFrac, Enum, Read), your own classes with default methods and superclasses, your own instances (also instance Show a => Show (Tree a)), overloaded functions and operators.
  • Functor, Applicative, Monad: do in any monad — Maybe, lists, Either e, IO and your own; fmap, <$>, <*>, >>=, mapM, forM_, when, foldM, replicateM, traverse, … (over lists).
  • Imports: Data.List, Data.Char, Data.Maybe, Control.Monad and friends are accepted (their functions are always available); Data.Map and Data.Set are real modules with qualified names.

A larger example, with a class, a record, a monad and a map:

import qualified Data.Map as M

data Account = Account { owner :: String, balance :: Int }
  deriving Show

class Describe a where
  describe :: a -> String
  describe _ = "something"

instance Describe Account where
  describe a = owner a ++ " has " ++ show (balance a)

withdraw :: Int -> Account -> Either String Account
withdraw n a
  | n > balance a = Left ("not enough money for " ++ owner a)
  | otherwise = Right a { balance = balance a - n }

transfer :: Int -> Account -> Account
         -> Either String (Account, Account)
transfer n from to = do
  from2 <- withdraw n from
  return (from2, to { balance = balance to + n })

main :: IO ()
main = do
  let ann = Account { owner = "Ann", balance = 100 }
      bob = Account { owner = "Bob", balance = 20 }
  print (transfer 30 ann bob)
  print (transfer 300 ann bob)
  mapM_ (putStrLn . describe) [ann, bob]
  let totals = M.fromListWith (+)
        [(owner a, balance a) | a <- [ann, bob, ann]]
  print (M.toList totals)

Records

data Point = Point { px :: Int, py :: Int } deriving (Show, Eq)

origin = Point { px = 0, py = 0 }                 -- fields in any order
moved = origin { py = 5 }                          -- update
mirror p@Point { px = x } = p { px = negate x }    -- record pattern

A missing field in a construction is only an error when it is used (GHC warns about it). Unknown or duplicated fields, and fields of the wrong constructor, are compile-time errors.

Your own monad

data State s a = State (s -> (a, s))

runState :: State s a -> s -> (a, s)
runState (State f) s = f s

instance Functor (State s) where
  fmap f (State g) = State (\s -> let (a, s2) = g s in (f a, s2))

instance Applicative (State s) where
  pure a = State (\s -> (a, s))
  State f <*> State g = State (\s -> let (h, s2) = f s
                                         (a, s3) = g s2 in (h a, s3))

instance Monad (State s) where
  State g >>= k = State (\s -> let (a, s2) = g s in runState (k a) s2)

tick :: State Int Int
tick = State (\n -> (n, n + 1))

label :: [a] -> State Int [(Int, a)]
label xs = mapM (\x -> do { n <- tick; return (n, x) }) xs

runState (label "abc") 0

([(0,'a'),(1,'b'),(2,'c')],3)

Libraries

Besides the Prelude:

  • Data.List: sort, sortBy, sortOn, group, groupBy, nub, partition, insert, delete, union, intersect, intercalate, intersperse, transpose, isPrefixOf, isSuffixOf, isInfixOf, stripPrefix, tails, inits, subsequences, permutations (in GHC's order), find, findIndex, elemIndex, scanl, scanr, zipWith3, unzip3, maximumBy, minimumBy; comparing and on.
  • Data.Maybe: fromMaybe, isJust, isNothing, catMaybes, mapMaybe, fromJust, maybe.
  • Data.Char: ord, chr, isDigit, isAlpha, isSpace, isUpper, toUpper, toLower, digitToInt, …
  • Control.Monad: mapM, mapM_, forM, forM_, sequence, sequence_, when, unless, replicateM, replicateM_, foldM, zipWithM, zipWithM_, join, void, liftA2, >=>, =<<.
  • Data.Map and Data.Set (also Data.Map.Strict): a weight-balanced tree as in the containers package, written in Haskell lite itself — fromList, fromListWith, insert, insertWith, delete, lookup, !, !?, member, findWithDefault, adjust, alter, update, toList, keys, elems, foldr, foldrWithKey, map, filter, union, unionWith, intersectionWith, difference, lookupMin, findMax, keysSet, … Use them qualified (import qualified Data.Map as M) or with an import list (import Data.Map (Map, fromList)). fmap works on a map.
  • read for Int and Double.

Tables and pictures in the notebook

A Haskell cell whose value has type Display is shown as a table, as Markdown or as a picture, just like the D. functions of Sapl cells:

table ["word", "count"] [[w, show (length ws)] | ws@(w : _) <- group (sort (words "the cat and the dog"))]
bar [3, 1, 4, 1, 5]
lineChart [sin (x / 10) | x <- [0 .. 60]]
plot [(x, sin x * exp (-x / 5)) | x <- [0, 0.1 .. 12]]
picture [disc yellow (0, 0) 0.6, disc black (-0.2, 0.2) 0.08, disc black (0.2, 0.2) 0.08]
column [markdown "# Result", text "plain text"]
  • table headers rows — rows of strings;
  • markdown, text, column (several displays below each other);
  • bar and lineChart (a list of Int or Double), plot (points (x, y), scaled to fit);
  • picture with shapes — disc, circle (centre and radius), rect, filledRect, ellipse, line, polygon, textAt — and colours such as black, red, blue, yellow. Coordinates run from −1 to 1, with (0, 0) in the middle.

Speed

Running time of the twelve core benchmarks of the repository, written as ordinary Haskell, relative to the same programs written by hand in Sapl (the JMVM's own language). For comparison: the MicroHs back-end, which uses the MicroHs front-end with a JMVM back-end and keeps type-class dictionaries at run time. Native JMVM, 7 November 2026; lower is faster.

Haskell liteMicroHs back-enddashed line: hand-written Sapl (1.0×)
BenchmarkHaskell lite (s)MicroHs back-end (s)Hand-written Sapl (s)Haskell lite / Sapl

Haskell lite code runs within 1.0–1.5× of hand-written Sapl (geometric mean 1.12×) and is as fast as or faster than the MicroHs back-end on ten of the twelve, because type classes are resolved at compile time. For sort and hamming most of the gap comes from Haskell's lazy list elements: the hand-written Sapl versions use lists with a strict head, which is faster but not Haskell's semantics. Knights and prolog have not been analysed yet.

For comparison with GHC: building a Data.Map with 200,000 insertWith operations takes 0.30 s; GHC with -O takes 0.10 s.

How it is tested

  • Running programs: 91 programs — the twelve benchmarks, programs for each feature, type classes, Double, Data.List, Data.Map, monads, records — run with Haskell lite and compiled with GHC (ghc -O). The output must be identical; 90 of 91 are. The one difference is an Int overflow (62 bits, see below).
  • Types: for 128 programs, the types Haskell lite infers are written back into the source as type signatures with their contexts. GHC must accept them (with -Wredundant-constraints) and give the same output. Programs with type errors must be rejected.
  • Parsing: for 57 programs the parse tree, printed back as Haskell with explicit braces and parentheses, is compared with the parse of MicroHs, before and after fixity resolution.
  • Notebook: browser tests in headless Chrome, for WebSapl and for the Workbench.

Differences from GHC

Numbers
Int is 62 bits (the JMVM's tagged integers), so overflow differs from GHC's 64 bits. Double is the JMVM's 32-bit float — as precise as Haskell's Float — and show prints it the way GHC prints a Float. There is no arbitrary-precision Integer.
Foldable and Traversable
They are not classes: sum, length, mapM, traverse, … work on lists. Use M.elems m for a map.
Fixity declarations
infixl 6 <+> is not supported; your own operators are infixl 9. The standard operators have their usual fixities.
Show
Your own Show instance is used as is, without showsPrec, so inside a constructor it gets no parentheses (Just Point 1 2 instead of Just (Point 1 2)). Derived instances, maps and sets do get them.
Records
No {..} (RecordWildCards) and no field puns.
read
Only for Int and Double.
Classes
Single-parameter classes only. There is no kind inference: an instance like instance Functor Int is rejected with a clear message. A failing pattern in a do of your own monad without MonadFail is a run-time error.
Modules
One module per program (in the notebook: all Haskell cells together). Imports of the standard modules are accepted; your own modules cannot be imported yet.
Notebook
Haskell cells and Sapl cells do not share definitions yet, and all Haskell cells are run again when one changes. Forms and interactive cells are only for Sapl cells.
